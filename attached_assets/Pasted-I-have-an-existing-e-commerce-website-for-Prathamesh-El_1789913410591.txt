I have an existing e-commerce website for **Prathamesh Electronics & Electricals** built in this Replit project.

I already have a customer-facing website and an admin page. I want you to restructure and connect them properly without unnecessarily rebuilding or breaking the existing customer website.

## MAIN GOAL

Create a professional e-commerce architecture similar in concept to large e-commerce websites such as Amazon:

* Customers see ONLY the normal shopping website.
* Admins have a completely separate, professional admin dashboard.
* Customers must NEVER be able to access or see the admin dashboard.
* The admin dashboard must require a secure login.
* The customer website and admin dashboard must use the same Supabase backend/database.
* Products, inventory, orders, customers, categories, etc. must be managed through the admin dashboard and reflected automatically on the customer website.

Do NOT copy Amazon's branding, design, logo, or copyrighted UI. I only want a similar separation between the customer storefront and administration system.

# 4. ADMIN AUTHENTICATION AND AUTHORIZATION

This is extremely important.

Do NOT rely only on hiding the admin page or checking a frontend variable.

For example, this is NOT sufficient:

if (user.email === "[admin@example.com](mailto:admin@example.com)") {
showAdmin();
}

Customers must not be able to bypass security by manually entering:

/admin
/admin/products
/admin/orders

into the browser.

Every protected admin route must verify that the currently authenticated Supabase user is actually an authorized administrator.

If an unauthenticated user visits:

/admin

redirect them to:

/admin/login

If a normal customer is authenticated but is NOT an admin, they must be denied access and redirected to the customer website.

Example:

Customer:

/admin
↓
ACCESS DENIED
↓
Redirect to /

Admin:

/admin
↓
Admin authentication verified
↓
Admin dashboard
